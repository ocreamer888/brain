# Brain — Persistent Memory System for Claude Code

The brain is a local vector memory system that gives Claude Code persistent, searchable knowledge across sessions. It captures what you build, the decisions you make, errors you fix, and patterns you discover — then surfaces relevant context automatically.

**Current state (2026-05-27):** ~17,400 memories. Rust API (`brain_api`) is the production path. Automated cleanup (BVH dedup, noise detection, title dedup, eval regression checks) runs after every session. Corpus self-regulates via cubic barrier.

## How It Works — Session Lifecycle

### Session Start (`session_start.py`)
```
Detect project from CWD → load last 3 session summaries → semantic search for related memories → inject as [BRAIN] context
```

### Every User Message (`user_prompt_submit.py`) — Strategy Layer
```
User types a message → read session state → check for:
  1. Pre-fetched error hints? → inject "Brain recall — similar past error: [solution]"
  2. Meaningful prompt (>20 chars)? → template_search → inject "Relevant brain context: [memories]"
  3. Short message? → silent (no injection)

Output printed to stdout → Claude Code injects into conversation context.
Zero cost (brain API search only, no LLM calls).
```

### During Session (`post_tool_use.py`)
```
Every tool call → classify action:
  Bash error?              → record in session state, wait for fix
  Edit/Write fixes error?  → save as "solution" with LLM title (confidence 0.9)
  Test pass after fail?    → save as "solution" with LLM title (confidence 0.85)
  Write new file?          → save as "solution" with LLM title (confidence 0.5)
  Edit source file?        → group by file, flush with LLM title when idle (confidence 0.5)
  Agent dispatch?          → save as "decision" (confidence 0.6)
  Read / ls / grep / .pyc? → skip (noise)

All saves gated by corpus barrier:
  threshold = 0.3 + 0.7 × ((n - 18k) / 7k)³    for n > 18k

All titles generated by LLM (gemini-2.5-flash-lite) — describes WHAT was done
and WHY, not just file names. Edit groups accumulate changes per file, flush
when idle (5 tool calls) or at session end with a single contextual memory.
```

### Session End (`session_end.py`)
```
Flush remaining edit groups → save with LLM titles

3-pass recycling loop (LLM-powered, ~$0.01/session):
  Pass 1: extract error→fix pairs  → save as "error_lesson" with LLM title
  Pass 2: extract decisions         → save as "pattern" with LLM title
  Pass 3: lean session summary      → save as "project_context"

Dedup guard: only first Stop event per session triggers saves.

Background processes (non-blocking):
  - Title dedup (every session, <1s)
  - BVH dedup (every session, ~2s)
  - Reflection (every session, ~5s)
  - Spool replay (every session, <1s)
  - Noise detection (every 20 sessions, ~12s)
  - Eval regression check (every 20 sessions, ~20s)
```

### Search (`search_brain` via MCP)
```
Classify query intent → type-biased retrieval:
  Troubleshooting ("why fails", "error", "broke") → boost solution + error_lesson
  Decision ("what approach", "what did we decide")  → boost decision + pattern
  Factual ("cost of", "how many")                   → boost fact
  Other                                             → general search

Rust API scoring: salience × recency × (α·cosine + (1-α)·BM25)
  α = 0.7 default, configurable per-request
  Type diversity cap: 40% per type in results
```

## Memory Types

| Type | What it captures | Created by |
|------|-----------------|-----------|
| `fact` | Verified data, metrics, timestamps | Fact backfill pipeline |
| `solution` | Bug fixes, implementations, error resolutions | PostToolUse hook (immediate fixes) |
| `error_lesson` | Error→fix pairs with cause and context | Session end recycling Pass 1 |
| `pattern` | Decisions, approaches, best practices | Session end recycling Pass 2 |
| `decision` | Agent dispatch descriptions | PostToolUse hook |
| `project_context` | Session summaries, high-level project state | Session end recycling Pass 3 |
| `conversation` | Chat, Q&A, dialogue | Historical ingests |

## Automated Cleanup Pipeline

Runs in background after every session end. No manual intervention needed.

| Process | Frequency | What it does | Log |
|---------|-----------|-------------|-----|
| Title dedup | Every session | Removes duplicate project_context with same (project, title) | `cleanup.log` |
| BVH dedup | Every session | Embedding-space duplicate detection with content-prefix narrow phase | `cleanup.log` |
| Noise detection | Every 20 sessions | Flags and deletes high-fragility memories (≥0.95) | `cleanup.log` |
| Eval check | Every 20 sessions | Quick gate + MCP P@1 check, logs REGRESSION if thresholds breached | `cleanup.log` |
| Reflection | Every session | Consolidates recent memories | `reflect.log` |
| Spool replay | Every session | Retries failed API saves | stderr |

### Corpus Barrier (self-regulating)

Prevents unbounded growth. As corpus approaches 25k, save threshold rises:

| Corpus | Threshold | Effect |
|--------|-----------|--------|
| ≤18,000 | 0.30 | Open — most signals save |
| 20,000 | 0.31 | Barely noticeable |
| 22,000 | 0.36 | Skips marginal saves |
| 24,000 | 0.67 | Only high-signal passes |
| 25,000 | 1.00 | Hard cap |

## Eval Framework

Four complementary modes:

| Mode | What it tests | Speed | Command |
|------|-------------|-------|---------|
| Quick gate | P@1 by memory type (no API) | ~20s | `--quick` |
| Kfold | Full corpus leave-one-out retrieval | ~3min | `--kfold` (via `retrieval_eval_kfold.py`) |
| Gold vault | Vault file recall accuracy | ~5s | `--vault` |
| MCP path | Real-world query quality through live API | ~30s | `--mcp` |

```bash
# Full suite
python3 brain/tools/eval_suite.py --all --quiet

# Individual modes
python3 brain/tools/eval_suite.py --quick
python3 brain/tools/eval_suite.py --mcp
```

### Current Baselines (2026-05-27)

| Metric | Value |
|--------|-------|
| Overall kfold P@1 | 0.923 |
| Non-fact kfold P@1 | 0.743 |
| MCP P@1 | 0.643 |
| MCP MRR | 0.758 |
| Quick gate (all types) | ≥0.997 |
| Gold vault recall | 1.000 |

### Regression Thresholds

| Signal | Threshold | Action |
|--------|-----------|--------|
| Any quick gate type < 0.45 | WARN | Check recent ingest |
| kfold-MCP gap > 0.30 | INVESTIGATE | Retrieval regression |
| Corpus > 20,000 | MONITOR | Barrier pressure increasing |

## Troubleshooting

| Symptom | Check |
|---------|-------|
| No context injected at session start | `brain_api` running? `curl localhost:8787/stats` |
| Memories not saving | Check `brain/hooks/cleanup.log` for barrier blocks |
| Retrieval quality dropped | `python3 brain/tools/eval_suite.py --mcp` |
| Corpus growing too fast | Check cleanup.log for dedup activity; lower barrier K |
| Duplicate memories appearing | Run `python3 brain/tools/bvh_dedup.py --dry-run` |
| High fragility score | Run `python3 brain/tools/noise_detect.py --sample 2000` |
